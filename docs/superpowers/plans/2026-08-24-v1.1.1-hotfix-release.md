# BS Coding v1.1.1 Hotfix Release Plan

**Goal:** Ship the quota auto-refresh and sub-agent chat scrolling fixes as `v1.1.1` through the existing tag-driven GitHub Actions release pipeline.

**Architecture:** Keep runtime changes limited to the existing provider scheduler and renderer scroll controller. Update package metadata and add a release-specific changelog, then verify locally before pushing `master` and tag `v1.1.1`.

**Tech Stack:** Electron, React, TypeScript, Vitest, Playwright, electron-vite, electron-builder, GitHub Actions.

---

## File map

- `src/main/index.ts`: already contains quota usage scheduler integration and post-turn refresh.
- `src/renderer/src/components/chat/chat-scroll-geometry.ts`: add testable wheel-intent decision helper.
- `src/renderer/src/components/chat/useChatScroll.ts`: use exact scroll-end state for wheel ownership.
- `tests/unit/chat-scroll-geometry.test.ts`: regression coverage for downward wheel behavior.
- `package.json`: bump application version to `1.1.1`.
- `package-lock.json`: synchronize package version metadata.
- `docs/changelog-1.1.1.md`: user-facing English changelog.

## Task 1: Finalize chat scroll regression fix

1. Review the three modified scroll files and run `git diff --check`.
2. Run `npm test -- --run tests/unit/chat-scroll-geometry.test.ts`.
3. Commit with `fix: release chat scroll during subagent streaming`.

## Task 2: Prepare v1.1.1 metadata

1. Run `npm version 1.1.1 --no-git-tag-version` to update both package files.
2. Create `docs/changelog-1.1.1.md` using `docs/changelog-format.md`.
3. Include quota auto-refresh and sub-agent scroll fixes under Bug Fixes.
4. Confirm `git diff --check` and inspect all release metadata.
5. Commit with `chore: prepare v1.1.1 release`.

## Task 3: Verify release candidate

Run, in order:

```bash
npm run typecheck
npm test
npm run build
npm run e2e -- tests/e2e/chat-scrollbar.spec.ts
```

Do not create the tag if any command fails.

## Task 4: Publish

1. Confirm clean worktree and inspect commits since `v1.1.0`.
2. Push `master` to the configured upstream.
3. Create annotated tag `v1.1.1` with message `BS Coding v1.1.1`.
4. Push tag `v1.1.1`.
5. Check GitHub Actions run for the tag and confirm the release pipeline starts.
6. After CI finishes, confirm GitHub Release assets include updater metadata and platform installers.

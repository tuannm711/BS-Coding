## What's changed

- **GitHub Copilot quota.** OAuth accounts load current account entitlement directly from GitHub, including Premium requests, Chat, Completions, remaining/request-limit counts, percentage, reported reset dates and Unlimited markers. New connections load quota immediately; Refresh and scheduled polling keep it current, preserving the last known data when the API is temporarily unavailable.
- **Copilot AI credits.** Show provider-reported credits used when present. GitHub does not always report an included-credit allowance or remaining balance; these are labeled as unreported rather than inferred from the subscription plan.
- **Correct account credentials.** Quota uses the GitHub identity token, never the Copilot runtime token. Imported credentials may retain an explicitly supplied GitHub identity token; runtime-only imports show an OAuth reconnect hint for quota.
- **Live Copilot model catalog.** Refresh and sign-in fetch the account's `/models` catalog instead of using a fixed two-model list. Enabled chat models with streaming/tool support are selected from reported policy, picker, plan restrictions and endpoints. Exact model names and context/output limits are stored. Chat Completions and Responses transports are supported; Messages-only and hidden/disabled models are filtered out. Account-specific API endpoints are honored only on trusted HTTPS Copilot hosts. A refresh failure preserves the last known catalog with an error, and an available selected model remains selected.

- **Conservative Copilot catalog.** Models must explicitly report `model_picker_enabled: true` and `policy.state: enabled`. Missing picker permission or policy state is excluded instead of assumed available. Refresh applies this filter to the account catalog; the list does not guarantee that every inference request will succeed.

Account entitlements do not establish which individual model consumes premium requests. Reported Copilot windows are informational for routing; actual runtime quota refusals remain authoritative.
